# Как делать релиз

Рабочая папка — `D:\myplugin`, GitHub-репозиторий — `paulnsk/myplugin`.

1. Закрыть nanoCAD. Запустить `powershell -ExecutionPolicy Bypass -File .\Pack.ps1 -Release`: скрипт соберёт плагин, обновит `artifacts\LATEST` и создаст версионный ZIP.
2. Проверить сборку и тесты. Major остаётся 0; релиз повышает minor, обычный билд — третий номер. После неудачной релизной сборки повторять без `-Release`, чтобы не повысить minor дважды.
3. Закоммитить согласованные изменения, создать аннотированный тег `v<версия>`, отправить коммит и тег в GitHub.
4. Публиковать через **GitHub REST API**: `gh` на машине нет. Токен получить командой `git credential fill`, передав ей через stdin `protocol=https\nhost=github.com\n\n`. Использовать поле `password` в заголовке `Authorization: Bearer <токен>`; токен не выводить.
   Делать это из **bash** (Git Bash) с `curl`: `token="$(printf 'protocol=https\nhost=github.com\n\n' | git credential fill | sed -n 's/^password=//p')"`. Из Windows PowerShell 5.1 не работает: git отвечает «refusing to work with credential missing protocol field» — и при передаче через конвейер, и при записи байтов в stdin процесса.
5. `POST https://api.github.com/repos/paulnsk/myplugin/releases`: поля `tag_name="v<версия>"`, `name="MyPlugin <версия>"`, `body="MyPlugin <версия>"`, `draft=true`.
6. Отправить ZIP через `POST` на полученный `upload_url`: убрать шаблон `{…}`, добавить `?name=<имя ZIP>`, передать файл с `Content-Type: application/zip`. Проверить размер и SHA256, если API вернул digest.
7. Опубликовать: `PATCH /repos/paulnsk/myplugin/releases/<id>` с `{"draft":false}`. Проверить страницу релиза и архив.

Описание релиза — только `MyPlugin <версия>`. После публикации пересобирать не нужно. Основную Hg-репу не трогать.
