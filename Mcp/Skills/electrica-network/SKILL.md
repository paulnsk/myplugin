# Шкафы и группы

Шкаф ElBoard создаётся objects_create с изделием из БД проекта; MountingHeightMm задаёт монтаж отдельно от XY. objects_structure показывает детей/порты. objects_add_child(id=шкаф) добавляет отходящую группу, возвращает её ID. types_describe(id=группа,query=...) раскрывает параметры: например PhaseVal, Label, GroupNumber, ReleaseCurrent. Не назначай фазы/номиналы наугад — используй руководство и реальные enum/шкалы изделия.

ports_connect(portId=группа,slaveIds=[потребители]) задаёт логическую связь; portId не равен ID шкафа. Вводные группы уже есть в структуре шкафа: отличай их от отходящих по свойствам. Для питания другого шкафа подключай его к отходящей группе вышестоящего. Связи проверяй через objects_structure(relation=slaves).

electrica_group_equipment_add(items=[{groupId,dbType,dbId}]) добавляет аппарат из БД проекта в группу без окна. Не заменяет старый аппарат. Найти существующий/новый аппарат — objects_structure; сменить изделие — objects_update.dbType/dbId, параметры — properties. Удаление старого аппарата требует согласованного намерения, иначе получится лишний аппарат. Не пользуйся objects_add_child на группе для выбора аппарата: штатный компоновщик открывает окно БД.

# Питание и расчёт

electrica_supply_get(items=[{boardId}]) показывает трансформатор и питающие кабели. electrica_supply_update задаёт transformerDbId и/или cables:[{dbId,lengthMeters,count}]; изделия DbElTransformer/ElWire заранее импортируются. Переданный список заменяет прежний целиком; без поля он сохраняется. Длина питающего кабеля в МЕТРАХ. Свойства режима питания шкафа меняются обычным objects_update после types_describe; устаревшие UsingWireDbId/LengthToTransformer не использовать.

После логических связей и реальной прокладки (electrica-cables) вызови electrica_calculate. Он перестраивает модель и запускает штатные расчёты мощности, тока, падения напряжения, КЗ/нагрева и проверки. mark=true также маркирует оборудование. Ответ — страница групп (по умолчанию10, максимум30), основные численные результаты и до5 проваленных проверок на группу. groupIds выбирает группы для ответа, не ограничивает расчёт. offset/limit ограничивают трафик. Успешный вызов не означает, что все инженерные проверки пройдены.

Настройки проекта/аппаратов читай и меняй точечно, затем пересчитывай. database_update(items=[{type,dbId,properties}]) меняет ТОЛЬКО БД проекта, не внешнюю. Изменение записи касается всех использующих её объектов: это отдельное осознанное действие. Значения из быстрого старта не выдавать за проверенный нормативный подбор.
