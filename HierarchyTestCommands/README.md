# Стенд иерархии

23.10.2026: папка перенесена в отдельный D:\myplugin\MyPlugin.sln.
Не включать обратно в продуктовые csproj и не коммитить в Mercurial.
Регистрация команд после NETLOAD ещё адаптируется; состояние — ../Notes/ПЕРЕНОС_В_ПЛАГИН.md.

- `CW_HIERARCHY_TEST_GENERATE_SAMPLE` — новый проект с обычными примерами.
- `CW_HIERARCHY_TEST_GENERATE_SAMPLE_ERROR` — отдельный проект с двумя совпадающими зонами. Запуск GENERATE3D показывает настоящую ошибку билдера о равных площадях.
- `CW_HIERARCHY_TEST_GENERATE3D` — обычное окно выбора, генерация и сохранение именованного DWG с записью selection.
- `CW_HIERARCHY_TEST_GENERATE3D_ALL` — верхние руты в порядке дерева. Первый дважды: нулевые координаты, затем X=12345, Y=−6789, Z=2345 мм и поворот −17°. Остальные один раз с нулевыми координатами.
- `CW_HIERARCHY_TEST_VALIDATE` — проверка всех сохраненных выгрузок текущего проекта.

ALL показывает настоящую форму для каждой выгрузки: открывает список, кликает по тексту рута, выбирает координаты в комбобоксе и нажимает OK. Во время обхода не двигать мышь и не переключать окна. При отмене или сбое автоматизации обход останавливается.

Ненулевой набор записывается в `AreaHierarchyMatrices.xml` тестового проекта перед первым показом формы в ALL. Пересоздавать стенд не нужно. Другие сохраненные наборы не удаляются.

В ALL сообщения генератора сохраняются, но предупреждающие окна и окно лога не показываются. Ошибка отдельной выгрузки попадает в итоговую сводку; остальные руты продолжают выгружаться. Ошибка билдера останавливает весь обход. При одиночной генерации вывод лога остается штатным. Сообщение о каждом сохранении DWG убрано из обеих команд.

Каждый DWG и JSON selection имеют отдельное GUID-имя; две выгрузки одного рута проверяются независимо. Поломка одной выгрузки не мешает проверять остальные.

В Г-образном примере надо вручную втянуть опорную точку малой зоны в территорию. Без этого результаты этого примера могут не пройти проверку. Паспорт и остальные примеры не меняем.
